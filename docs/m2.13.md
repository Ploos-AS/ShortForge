# M2.13 — Resumable publishing recovery

YouTube video uploads now recover according to the resumable upload protocol.

- HTTP 500, 502, 503 and 504 are retriable.
- Interrupted transport errors are retriable.
- ShortForge queries the session with `Content-Range: bytes */TOTAL` rather than guessing how much YouTube received.
- A `308 Resume Incomplete` `Range` response determines the next byte offset.
- Resumed PUT requests send only the remaining bytes with an explicit `Content-Range`.
- Retries use bounded exponential backoff and a finite retry limit.

ShortForge intentionally keeps the normal single-transfer approach rather than forcing chunked uploads: YouTube documents chunking as useful for unstable links but normally unnecessary because it increases request count. The resume protocol provides recovery without that overhead.
